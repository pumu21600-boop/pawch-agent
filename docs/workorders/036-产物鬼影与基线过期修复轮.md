# 036 · 产物鬼影与基线过期修复轮（用户实锤三连）

> 排期来源：UI 嫁接轮回退（035）后用户复验实锤——「产物列表不是当前工作区的」「列表压扁」「滑条与对话框重叠」，点名修产物 bug。
> 纪律：窄而刚——只修产物/基线数据链路；列表压扁与滑条重叠先归因再动（压扁疑似 v0.32.40 期截图 + 鬼影内容伴生，滑条重叠用户自述疑似旧问题）。

## 一、根因链（全部真机/单测实证）

1. **鬼影根因 `tracked_files` 存在性过滤**（src/recovery/mod.rs）：`let Ok(meta) = std::fs::metadata(&full) else { continue }` ——工作区里已删除/被挪走的跟踪文件直接被丢出 pathspec，`git add` 永远收不到删除 → 影子仓库的基线把鬼影文件**一代代往后传**，产物/git 面板永久挂着幽灵条目 + stale 警告每次都触发。
   - 排查路径：UI 点「重拍」无效果 → 浏览器直 fetch 端点发现 ok:false「没有可跟踪文件」→ 发现 checkpoint 的 None 语义有两义（非 git / 无变更）→ 逐层探针（spec 内容 → add 退出码 → 影子 index → rev-parse 探针）最终定位 tracked_files 的 metadata 过滤。
2. **基线过期无处安放**：stale_subtree_warning 只会给一句话警告，清单照挂。修法：前端检测到 stale → 隐藏清单（计数说明）+「重新以当前状态为起点」按钮 → 新端点重拍。
3. **POST /api/checkpoints（新端点）**：手动重拍基线。checkpoint 的 None 双义处理——无变更时回指最近一个已有检查点（它就代表当前状态）+ 人话 note；非 git 工作区 ok:false + 人话。归属带上的会话。
4. **git add 加 `-A` 双保险**：pathspec 含已删除路径时个别形态下默认 add 会 fatal；另加容错重试（从未入过基线的删除文件剔除后重试，不构成任何基线差异）。

## 二、交付

- **后端**：`src/recovery/mod.rs`——tracked_files 保留已删除跟踪文件（保留尺寸/非文件过滤）；checkpoint 的 add 加 `-A` + fatal 容错重试。`src/server/git.rs`——POST /api/checkpoints（手动重拍基线，None 双义处理）。`src/server/mod.rs`——路由注册。
- **前端**：`web/src/App.svelte`——产物/git 两面板的基线过期态（隐藏清单 + 计数说明 + 重拍按钮）；resolveBaseline 增加 manualBaseline 优先级（重拍结果压过消息流旧检查点）；会话/工作区切换重置 manualBaseline 与 stale 态。
- **测试**：`recovery::tests::checkpoint_records_worktree_deletions`（删除必须入基线 + 新基线无鬼影 + 旧基线如实报删除）；`http_tests::manual_checkpoint_endpoint_contract`（非 git 人话 / ok:true 归属 / 无变更回指最近检查点）。

## 三、验证口径与记录（2026-10-31）

- **闸**：cargo test 514 过（+2 新）/ clippy -D warnings 零告警 / npm test 23 过 / build / check_fetch（94 点）/ check_md_css。
- **真机**（5277 临时 git 工作区复刻用户现场）：建仓→拍基线→挪走 src/screenshots 目录→产物面板出现过期态（警告 + 已隐藏 N 个基线残留条目 + 重拍按钮，鬼影清单不渲染）→ 点重拍 → 新检查点归属当前会话 → 横幅消失、清单回到真实增量 → 再改文件后清单如实只列该文件。Tabbit DOM 断言全过。
- **清理**：临时进程按 PID 杀净，实验目录全删。

## 四、明确不做 / 遗留

- **列表压扁**：用户截图的滚动条样式是 v0.32.40 期特征（圆角悬浮条），疑似旧构建截图；且压扁清单内容 = 鬼影长路径，鬼影清除后大概率消失。待用户刷新复验，仍压扁则按 .rv-file 长路径 flex 布局单独修。
- **滑条与对话框重叠**：用户自述疑似旧问题，单独排查（需用户刷新后截图定位）。
- 本单不碰 035 已回退的任何 UI 项。

# 035 · UI 生态嫁接轮（高亮 / 字体 / 图标 / 滚动条 / 令牌声明）

> 排期来源：UI 优化调研 + Svelte 5 迁移轮（034）解锁生态；用户拍板「都一起做」「滚动条怎么好看怎么来，不影响功能就行」。
> 路径：点状嫁接——只有 Shiki / 字体 / OverlayScrollbars 走 npm 依赖，图标与令牌手工抄写；每件独立提交，真机验收过一件是一件。
> 纪律：窄而刚——不做整体视觉翻新（上次「视觉刷新」被回退的教训），不动任何交互行为；虚拟列表（TanStack Virtual）本轮只评估不动刀。

## 一、范围（本单交付）

### 件 1 · Shiki 代码高亮
- `npm i shiki`；`web/src/lib/highlight.js`：懒加载 `shiki/core` + JS 引擎（不用 WASM）+ 按需语言（ts/js/json/rust/python/bash/css/html/sql/yaml/markdown/diff）。
- 双主题 `github-dark` / `github-light`，`defaultColor: false` + CSS 变量模式，跟 `[data-theme]` 联动，切换主题即时生效不重排。
- 接入点：App.svelte 既有 afterUpdate 渲染后处理（data-mt 补盖同一处），`enhanceCodeBlocks()` 只处理 `.md-codeblock` 里未标记的 code，读 textContent（天然反转义）→ Shiki 输出安全 HTML 回填；流式重渲染导致节点重建时自动重标。**不碰 md.js 的 escape-first 管线。**

### 件 2 · 字体本地打包
- `npm i @fontsource-variable/inter @fontsource-variable/jetbrains-mono`；main.js 引入。
- ui.css：正文 `'Inter Variable', 'Segoe UI', 'Microsoft YaHei', …`；代码 `'JetBrains Mono Variable', Consolas, …`。中文继续系统字体（中文字体包体积不值）。

### 件 3 · 图标统一（Lucide，只抄不装）
- `npm i -D lucide-static` 作为抄写源；把手绘 SVG 里风格出格的换成 Lucide 等义图标（内联 SVG，零运行时）。
- 全局约束补齐：图标尺寸/线宽用 CSS 统一（现有 `.nav-ico` 等类对齐 stroke-width 1.8）。

### 件 4 · 滚动条（OverlayScrollbars）+ 令牌打底
- `npm i overlayscrollbars`；主滚动容器接管：聊天区 `.chat-body`、侧栏 `.side-scroll`、右面板滚动容器。悬浮式自动隐藏（leave），底下保持原生滚动——scrollTop/scroll 事件语义不变，自动跟随/引导跟随不受影响。
- 主题配色用 CSS 变量覆盖（OS v2 主题就是一组 CSS 变量），`[data-theme]` 各配一套，一处初始化双主题生效。
- Open Props 抄写：缓动曲线 + 三档阴影进 ui.css 变量（`--ease-*` / `--shadow-*`），本轮只供新样式使用，不做全量视觉替换。

### 真机（5274 隔离实例 + 代码块剧本 mock，Tabbit DOM 断言）
- 高亮：python 代码块出 shiki span、lang 标签/复制钮在、textContent 完整；span 携带 `--shiki-light/--shiki-dark` 双变量；产物 CSS 含 `[data-theme]` 双规则；**node 复现 codeToHtml 输出 light≠dark（#D73A49/#F97583）**——双主题链路三件套实锤。

- 主题切换/刷新/工具轮无回归。

### ⚠️ 环境坑（以后 Tabbit 验色必看）
**Tabbit 浏览器护眼模式会改写页面颜色**：内联 style 都动（探针 `#FF7B72`→`rgb(229,158,153)`，hue 挪到 354），并给元素注入 `--*--night-eye` 系列变量——shiki span 的 light/dark 变量被改成同值，直接断言「双主题色差」会误判失败。判决实验=页面里造内联色探针看是否被改写。验色用「node 复现 + 产物 CSS 规则 + DOM 变量在位」三件套替代。

### 虚拟列表评估（本轮不动刀）
现状=分块 content-visibility（`.cv-chunk` 140px/条估高）。TanStack Virtual 可接（与 OS 共用 scroller 无冲突），但要动三处既有假设：mergeAssistantRun 派生数组的稳定 key、多选/回滚对「DOM 存在」的依赖、流式增长的动态测高——属显示管线手术，收益（DOM 节点坍缩）真实但回归面大，留独立件待长会话卡顿再实感驱动。

### ⚠️ 补丁回滚（2026-10-31 晚，用户实锤「划不动对话界面」→ v0.32.40）
- **回归**：OverlayScrollbars 接管聊天区后真人滚轮完全失灵。根因链：OS v2 **必然重构滚动容器 DOM**（宿主 `overflow:hidden !important` + 自建 viewport 子元素）——「data-overlayscrollbars-initialize=宿主当视口、DOM 不重构」是**错误假设**；而本应用自动跟随/钉底判定/引导滚动全部写死在宿主 `chatBody.scrollTop` 上，宿主不可滚后两套状态互殴，真人滚轮实测位移为 0（035b 复现：wheel 前 after 均 0）。
- **验证方法教训**：此前「自动跟随无损」的断言（atBottom 判定）在不可滚容器上**恒真**，属无效验证——**滚动类断言必须用真人滚轮（mouse.wheel）看 scrollTop 位移量**，且滚轮数据要先于其它可能失败的断言单独取。
- **处置**：OS 整体回滚（依赖卸载 + 三容器属性/导入/ensure 移除），滚动条美化降级为**纯 CSS**（`::-webkit-scrollbar` 宽 10px 圆角 thumb，theme 色阶配色，零 JS 零风险）；高亮/字体/图标不受影响保留。修复版真机重验：真人滚轮位移恢复（2257→1100）、上滑出「回到底部」、点击回底 atBottom=true、OS 残留 0、高亮 python span 正常、Inter 字体在位。

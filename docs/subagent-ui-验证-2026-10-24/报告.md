## 二、内置浏览器：child webview 建立失败 ❌（P0，独立缺陷）

**现象**：任何「开网页」动作（agent 工具 / 面板粘贴 URL / API 直调）一律报
「等待桌面壳 webview 上线超时（CDP 端口 9223 不可用？被别的程序占了？）: 8s 内没出现新的 page target」。
子代理拿到该错误文本后如实汇报（子代理机制本身无辜）。

**证据链**（2026-10-24 下午实测）：
1. 服务端 `shell_create_target`（`src/browser/session.rs:210`）流程走到位：壳控制通道
   9225 ESTABLISHED、`shell::create` 指令送达、壳侧 `add_child` 返回 Ok（壳日志连续
   `create wv-N about:blank ... visible=false`）。
2. 但 8s 内 CDP 端点 `http://127.0.0.1:9223/json/list` 里**只有壳主窗口一个 target**，
   child webview 的 page target 从不注册 → 服务端超时回收（壳日志 `close wv-N`）。
3. 进程级实证：create 窗口期内 `msedgewebview2.exe` 壳进程组（user-data-dir=
   `com.pawch-agent.desktop`）**没有新增 renderer 进程**——child webview 的渲染进程
   根本没被拉起（`add_child` 返回 Ok 但 WebView2 未初始化 renderer）。
4. 排除项：WebView2 运行时 153.0.4234.48 于 9/20 安装后未变；desktop/ 代码一个月未改
   （只改过名）；9223 端口本身健康（主窗口 target 在列）；`/json/new` 不通属 WebView2
   正常限制。
5. 变量：壳与服务 exe 均为 10-24 当天重构建（壳 11:33 / 服务 13:25）。9/20 WebView2 更新
   与本次重构建之间无「新建 child webview 成功」的真机记录（E2E 10-24 只测了总闸联动，
   未真开网页）——回归窗口 = 9/20 运行时更新 ~ 10-24，具体引入点未定位。

**修复方向候选**（待拍板，未动手）：
- 壳侧 `add_child` 后主动验证 renderer/target 真起了（现在是服务端盲等 8s）；
- 排查 wry/tauri 对 child webview 的环境复用（additional_browser_args 对第二个 webview
  是否仍生效）；
- 兜底：shell 模式建 target 连续失败 N 次后自动降级无头模式（现在只报错不降级，
  `PAWCH_AGENT_BROWSER_HEADLESS=1` 需要重启服务才生效）。
